Adds `defaults.threadpoolLimit` (default 4), rendered as `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS`, `NUMEXPR_NUM_THREADS`, `VECLIB_MAXIMUM_THREADS` and `BLIS_NUM_THREADS` on every worker, per the upstream [memory use guide](https://climate-ref.readthedocs.io/en/latest/how-to-guides/control-memory-use/#limiting-openmp-and-blas-threads).
This stops numpy/scipy sizing their thread pools off the host core count and oversubscribing the CPUs on large nodes.
Tune it per provider via `providers.<name>.threadpoolLimit`, or set an individual variable in `env` to win over the cap.
